### DBMS 이해를 위한 학습 목차


**[1. DBMS는 왜 등장했나 (역사와 배경)](./01-background.md)**

- 파일 시스템으로 데이터를 관리할 때 생기는 문제: 중복, 불일치, 동시 접근, 장애 복구, 보안
- 계층형 DB와 네트워크형 DB에서 관계형 DB로의 흐름 (Codd의 관계형 모델, SQL의 탄생)
- 이후의 흐름: RDBMS 전성기, NoSQL(Redis 등)의 등장, 지금의 공존

**[2. 언제, 왜 DBMS를 쓰나](./02-when-to-use.md)**

- 파일 저장, 엑셀, DBMS 비교
- RDBMS와 NoSQL의 선택 기준
- 서비스 구조에서 DBMS가 놓이는 자리(앱 서버 ↔ DB)

**[3. 사용자가 실제로 쓰는 기능](./03-how-to-use.md)**

- SQL 기본: INSERT, SELECT, WHERE, UPDATE, DELETE
- 테이블, 스키마, 기본 키(PK), 자동 증가 ID
- 인덱스는 어떤 상황에서 왜 쓰는지
- 트랜잭션과 ACID, 동시성 제어(락)
- 백업과 복구, 사용자 권한
- 직접 체험하기: SQLite나 MySQL로 간단한 테이블을 만들고, EXPLAIN으로 - 인덱스 유무에 따른 차이 확인

**[4. DBMS 내부 구조 (과제와 직결)](./04-how-it-works.md)**

- 전체 처리 흐름: 클라이언트 → 파서 → 옵티마이저 → 실행 엔진 → 저장 엔진
- SQL 파싱: 토큰화, 구문 분석, 구조화된 결과(AST)
- 저장 방식: 레코드와 페이지, 힙 파일, CSV/바이너리 포맷 설계의 트레이드오프

**[5. 인덱스와 B+ 트리](./05-index-b-plus-tree.md)**

- 선형 탐색 O(N)과 트리 탐색 O(log N)
- B 트리와 B+ 트리의 차이, 노드 분할과 병합
- 디스크 기반과 메모리 기반의 차이
- WHERE id = ?에서 인덱스를 타는 경로와 못 타는 경로

**[6. 동시성과 서버 구조](./06-concurrency.md)**

- 스레드 풀 개념과 요청 처리 흐름
- 경쟁 상태(race condition), 뮤텍스, 읽기/쓰기 락
- 엔진과 API 서버 사이의 인터페이스 설계

**[7. 실제 DBMS 사례 살펴보기](./07-case-studies.md)**

- SQLite(가장 단순한 구조, 이번 과제와 가장 비슷함)
- MySQL(InnoDB)의 B+ 트리 인덱스
