# 7. 실제 DBMS 사례 살펴보기

> - SQLite(가장 단순한 구조, 이번 과제와 가장 비슷함)
> - MySQL(InnoDB)의 B+ 트리 인덱스

---

## SQLite
- 특징 : 별도의 DB 서버에 접속하는 방식이 아니라, 애플리케이션 안에서 실행되는 DBMS
  - SQLite 라이브러리를 통해 SQL을 실행, 데이터베이스 '파일'을 다룸.
  - 별도 서버를 운영하지 않아도 된다는 특징.
  - 단순한 "파일 읽기 도구"는 아님. SQL 해석, 데이터 관리 등의 DBMS 기능이 앱 안에서 동작
- 과제 : Phase 01의 파일 기반 SQL 처리기도 별도 서버 없이 시작함.
- 인메모리 DB인가?
  - SQLite는 기본적으로 '파일에 저장하는 DBMS라고 보는 게 적절'
  - 다만, 저장 위치를 `:memory:`로 지정하면, 파일 대신 메모리에만 존재하는 DB로도 사용할 수 있음
- 데이터 파일은 앱 서버와 함께 빌드되는가?
  - 데이터 파일이 앱 서버와 반드시 함께 빌드될 필요는 없음 (지정한 경로에 파일이 존재하거나 파일을 생성할 수 있으면 됨)
  - 중요한 것은 '실행 중인 앱이 해당 경로에 접근할 수 있는가?'

---

## MySQL InnoDB
- 특징 : 기본 키를 클러스터드 인덱스로 사용
  - B+ 트리의 리프에 행을 찾기 위한 주소만 있는 게 아니라, 행 데이터가 함께 저장됨 (한 번 더 찾아가지 않아도 됨)
  - 특정 키 순서 없이 행을 담는 "힙 파일"과 차이가 있음
- 리프에 데이터를 함께 담았을 때의 이점 : **범위 조회**
  - 가까운 키의 행을 읽을 때 이미 가져온 페이지를 그대로 활용해서 데이터를 읽을 수 있음
