# 학습 확인과 구현 후 검증 항목

> 현재는 구현 전입니다. 아래 항목은 학습 내용으로부터 정리한 확인 기준이며, 단위 테스트·기능 테스트를 실행한 결과가 아닙니다.

## 대화에서 확인한 이해

| 항목 | 확인한 내용 |
| --- | --- |
| SELECT 처리 | 조건을 통과한 행에서 필요한 컬럼을 가져온다 |
| 테이블 스캔 | 다음 행을 계속 읽으며, 더 읽을 행이 없으면 끝을 알린다 |
| INSERT 대응 | 명시한 컬럼 목록과 값 목록의 같은 위치를 연결한다 |
| 목록 개수 | 컬럼 수와 값 수가 다르면 오류로 처리한다 |
| 스키마 순서 | 컬럼 생략 예제에서는 정의된 순서로 대응한다고 이해했다 |
| append | 새 행을 뒤에 추가하되 끝을 찾으려고 전 행을 읽을 필요는 없다 |
| 저장 형식 | 저장·읽기 규칙이 다르면 원래 값을 복원하지 못한다 |

이는 대화 중 답변을 확인한 범위이며 독립적인 평가나 구현 검증은 아닙니다. 명시한 컬럼 이름으로 스키마를 찾는 방식과 CSV 해석 후 자료형 적용은 설명을 들었지만 추가 확인은 남아 있습니다. DBMS 배경 노트도 이번에 보충한 내용이므로 이해도 확인 전입니다.

## 현재 범위에서 구현 후 확인할 사례

아래 SQL은 확인하려는 동작의 예시입니다. 최종 지원 문법·자료형·저장 형식과 오류 정책을 정한 뒤 실제 테스트로 옮겨야 합니다.

| ID | 입력 또는 상황 | 확인할 결과 |
| --- | --- | --- |
| P1-01 | SELECT name FROM users WHERE id = 1 | 작업·테이블·컬럼·조건이 구분된다 |
| P1-02 | 조건의 1과 '1' | 숫자와 문자열 리터럴의 구분이 보존된다 |
| P1-03 | 존재하지 않는 테이블 또는 컬럼 | 스키마 검사에서 실패하고 파일을 변경하지 않는다 |
| P1-04 | INSERT의 컬럼 2개, 값 1개 | 개수 불일치로 거부하고 기존 데이터가 유지된다 |
| P1-05 | (age, name)에 (25, '영희') 삽입 | 이름을 기준으로 실제 컬럼에 배치된다 |
| P1-06 | 정수 컬럼에 'abc' 삽입 | 자료형 정책에 따라 거부하고 파일을 변경하지 않는다 |
| P1-07 | 기존 행이 있는 파일에 INSERT | 기존 행을 유지하고 새 행이 추가된다 |
| P1-08 | CSV 후보에서 김,철수 또는 김"철수 저장·읽기 | 쉼표·따옴표를 포함한 원래 값이 복원된다 |
| P1-09 | CSV 텍스트의 age를 복원한 뒤 숫자 조건 검사 | 스키마에 맞게 해석한 값으로 비교한다 |
| P1-10 | 조건 일치 행이 0개·1개·여러 개 | 해당 결과 수대로 반환한다; 중복 행 예제는 중복 허용 스키마를 가정한다 |
| P1-11 | 빈 테이블 또는 마지막 기록까지 읽음 | 정상 종료하며 무한 반복하거나 마지막 행을 누락하지 않는다 |

P1-08은 CSV를 선택할 때의 기준입니다. 다른 형식을 선택하면 그 형식의 특수 문자와 값 복원 사례로 바꿉니다.

가장 직접적인 저장 형식 확인은 **같은 행을 저장하고 다시 읽었을 때 값과 자료형이 원래와 같은지** 보는 것입니다. 아직 이 검사를 실행하지 않았습니다.

## 학습과 정책 결정이 더 필요한 경계 사례

SQL의 따옴표·문법 오류, 중복 컬럼 명시, 컬럼 생략·기본값, CSV의 줄바꿈·NULL·인코딩, 파일 손상·쓰기 실패는 추가 학습과 정책 결정이 필요합니다. 지금 단계에서 기대 동작을 임의로 확정하지 않습니다.
