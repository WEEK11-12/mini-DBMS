# 학습 범위와 기록 기준

## 이번 과제의 목표

Phase 1에서 만든 SQL 처리기를 Phase 2와 Phase 3에서도 재사용합니다. Phase 1은 INSERT / SELECT와 파일 저장, Phase 2는 메모리 기반 B+ 트리 인덱스와 100만 건 이상의 성능 비교, Phase 3은 API 서버와 스레드 풀 병렬 처리가 목표입니다. 스키마와 테이블은 이미 존재한다고 가정하며 CREATE TABLE은 필수가 아닙니다.

이 내용은 [과제 요구사항](../assignment.md)의 요약이며, 각 기능을 학습하거나 구현했다는 의미는 아닙니다.

## 기록 방식

- 학습한 개념과 예제, 질문을 통해 바뀐 이해를 기록합니다.
- 일반적인 DBMS 개념과 이번 과제에서 실제 채택한 구조를 구분합니다.
- 학습하지 않은 주제는 빈 노트로 남기고 목차에 상태만 표시합니다.
- 아직 설계, 코드 작성, 단위·기능 테스트, 성능 실험은 진행하지 않았습니다.

## 현재 이해의 범위

SELECT 요청이 구조화되고, 스키마 정보로 의미를 확인한 뒤, 선택한 실행 방법으로 행을 읽고 조건을 검사해 필요한 컬럼을 반환한다는 흐름을 공부했습니다.

인덱스의 검색 범위 축소 효과와 유지 비용을 이야기했지만, B+ 트리의 내부 동작, 파일 저장 형식, API·스레드 풀·동시성은 아직 공부하지 않았습니다.

전체 학습 지도를 [목차](README.md)에서 확인합니다.
