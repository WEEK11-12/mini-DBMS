# 학습 범위와 기록 기준

기록 기준: 2026-11-16. [과제 원문](../assignment.md)을 기준으로 Phase 1~3 전체 학습 노트를 마련했습니다.

## 문서와 실제 진도를 구분한다

- **대화 학습**: 이 세션에서 설명하거나 질의응답한 범위입니다. 독립적인 이해도 평가를 통과했다는 뜻은 아닙니다.
- **예습 정리**: 앞으로 공부할 내용을 이번 요청에 따라 먼저 채운 것입니다.
- **선택한 정책**: SQL 파일 실행 중 첫 실패가 발생하면 이후 문장을 실행하지 않습니다. 앞서 성공한 문장은 유지하며, 전체 롤백은 보장하지 않습니다.
- **설계 후보**: 저장 형식, 언어·프레임워크, 노드 용량, 락 범위, API 계약은 아직 선택하지 않았습니다.

기존의 “학습 전 파일은 비워 둔다”는 방식은 이번 요청에 따라 변경했습니다. 이제 모든 학습 파일에 내용을 두되, 실제 진도와 예습을 각 노트에서 구분합니다. README는 저장소 루트에만 두고 main의 원문을 유지합니다.

## 과제의 연결 구조

```text
Phase 1: CLI → SQL 파싱·스키마 확인·실행 → 테이블 파일
Phase 2: 같은 SQL 처리기 → ID 조건은 B+ 트리 → 테이블 파일
Phase 3: API → 스레드 풀 → 같은 내부 엔진 → 파일 + B+ 트리
```

SQL 처리기를 Phase마다 새로 만들지 않습니다. 복잡한 옵티마이저나 디스크 기반 B+ 트리 전체를 복제하는 과제가 아닙니다. 스키마·테이블은 존재한다고 가정하고 CREATE TABLE은 필수가 아닙니다.

## 실제로 어디까지 다뤘는가

Phase 1은 SQL 흐름, AST, 스키마, SELECT·INSERT, 테이블 스캔, append와 CSV 예제, CLI, 오류 중단 정책, 기본 테스트 개념까지 다뤘습니다.

Phase 2는 내부 노드와 리프, 탐색 경계, 리프 삽입·분할, 처음의 루트와 루트 분할 시 높이 증가까지 설명했습니다. 내부 노드 분할 이후의 상세 불변 조건, 파일 연결·재시작·성능 측정과 Phase 3은 예습입니다.

현재 구현·DBMS 기능 테스트·성능 측정 결과는 없습니다. 노트 완성이 곧 학습이나 구현 완료는 아닙니다.

## 각 Phase에서 설명할 수 있어야 할 것

Phase 1에서는 SQL 한 문장이 어떻게 AST가 되고 스키마를 거쳐 파일 읽기·쓰기로 연결되는지, 오류 후 어떤 데이터가 남는지 설명할 수 있어야 합니다.

Phase 2에서는 경계 키와 자식 범위, 리프·내부 분할의 차이, ID가 파일 위치로 연결되는 과정, 재시작 시 복원과 측정 조건을 설명할 수 있어야 합니다.

Phase 3에서는 요청이 어느 스레드에서 실행되는지, ID·파일·인덱스가 어떤 잠금으로 함께 보호되는지, 과부하·오류·종료 시 어떻게 처리하는지 설명할 수 있어야 합니다.

## 설계로 넘어갈 때 결정할 항목

언어, 지원 SQL 문법, 스키마 표현, 파일 형식·레코드 위치, 오류 시 보장 범위, ID·재시작 정책, 트리 용량, API 계약, 풀·대기열 한도, 동시성 범위, 검증 기준을 결정합니다. 각 결정에는 실패 사례와 확인 방법을 붙입니다.

차별점은 우선 필수 기능을 검증한 뒤 선택합니다. 실행 경로 표시, B+ 트리 분할 시각화, 재현 가능한 벤치마크 보고서 같은 후보가 있습니다. 아직 구현 약속은 아닙니다.

기존 ChatGPT 대화에서 확인하지 못한 답변을 학습 증거로 삼지 않습니다. 이 세션의 실제 대화와 이번 예습 보충을 기준으로 기록합니다.
