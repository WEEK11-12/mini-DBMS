# SQL 처리 전체 흐름

## 사용한 예제

```sql
SELECT name FROM users WHERE id = 1;
```

요청은 users 테이블에서 id 값이 1인 행들의 name을 가져오는 것입니다.

## 단계별 역할

| 단계 | 하는 일 |
| --- | --- |
| 파싱 | SQL 문장을 읽어 작업 종류, 테이블, 컬럼, 조건을 구조화 |
| 스키마 확인 | 테이블·컬럼 존재 여부와 자료형 등 의미 확인 |
| 실행 방법 선택 | 테이블 스캔 또는 사용 가능한 인덱스 탐색 등 방법 선택 |
| 실행 | 행을 읽고 조건을 적용해 결과 생성 |

이는 이해를 위한 일반적인 구분입니다. 이번 과제에서 복잡한 옵티마이저를 구현하기로 결정한 것은 아닙니다.

## 논리적 처리 순서와 파서의 읽기

SELECT 예제의 논리적 처리 순서는 FROM → WHERE → SELECT로 생각할 수 있습니다. 대상 테이블에서 조건에 맞는 행을 남기고 필요한 컬럼을 가져온다는 뜻입니다.

파서가 문장을 읽는 순서와는 구분해야 합니다. 파서는 문장에 적힌 SELECT, FROM, WHERE 등의 문법 구조를 분석합니다. FROM부터 읽어야 한다는 뜻이 아닙니다.

## 용어를 바로잡은 부분

실행 방법을 고르는 역할은 보통 **옵티마이저**라고 부릅니다. **오퍼레이터**는 Table Scan, Filter, 컬럼 선택처럼 실행 계획을 이루는 작업 단위입니다. 실행기는 그 작업을 수행합니다.
