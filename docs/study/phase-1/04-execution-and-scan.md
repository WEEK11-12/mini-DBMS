# 실행기와 테이블 스캔

## 행을 처리하는 순서

```sql
SELECT name FROM users WHERE id = 1;
```

```text
행 읽기 → id가 1인지 검사 → 맞으면 name을 결과에 추가
```

| 행 | Filter 결과 | 출력 |
| --- | --- | --- |
| (2, "민수") | 탈락 | 없음 |
| (1, "영희") | 통과 | 영희 |
| (1, "철수") | 통과 | 철수 |

Filter는 어떤 행을 남길지 결정하고, 컬럼 선택은 남은 행에서 무엇을 보여줄지 결정합니다. 이 예제는 id 중복이 허용된 상황을 가정합니다. id가 기본 키라서 중복이 금지된다면 id = 1의 결과는 최대 한 행입니다.

## Table Scan

테이블 스캔은 행을 차례로 읽는 방식입니다. 여기서 순회하는 대상은 테이블의 행입니다. 인덱스의 모든 항목을 읽는다는 뜻이 아닙니다.

조건에 맞는 행이 마지막에 있다면 그 앞의 행들도 읽어야 합니다. id가 고유하다는 보장이나 결과 수 제한이 없다면 일치하는 행을 발견한 뒤에도 나머지 행을 확인해야 결과를 빠뜨리지 않습니다.

## 행을 하나씩 요청하는 설명 모델

```text
다음 행 요청
→ Table Scan이 한 행 반환
→ Filter가 조건 검사
   → 불일치: 다시 다음 행 요청
   → 일치: 컬럼 선택 단계에 전달
→ 더 읽을 행이 없으면 종료
```

조건에서 탈락한 행은 다음 단계로 전달되지 않습니다. 전체 실행이 멈추는 것은 아니며 다음 행을 검사합니다. 이 방식은 개념 설명이며 실제 과제의 실행기 인터페이스는 미정입니다.

## 끝을 어떻게 아는가

배열을 예로 들면 [A, B, C]에서 현재 위치를 0, 1, 2로 옮겨 읽고 위치 3에서는 더 읽을 행이 없다고 판단할 수 있습니다.

마지막 행에 특별한 표시를 붙이는 것이 필수는 아닙니다. 저장 구조와 읽기 인터페이스에 따라 더 읽을 행이 없음을 판단하고 null이나 별도 상태값 등으로 알릴 수 있습니다. 실제 파일에서 끝을 판단하는 구현은 아직 공부하지 않았습니다.

## 예습: 실행기의 입출력과 파일 끝

공통 실행기가 구조화한 요청을 받아 행 목록·컬럼 목록 또는 삽입 결과를 반환하게 하면 CLI와 API가 재사용하기 쉽습니다. 출력 문자열을 실행기에서 직접 찍는 방식은 두 입구를 연결할 때 재검토해야 합니다.

파일 읽기가 정상 EOF를 알린 경우와, 한 레코드를 읽다가 형식 오류·I/O 오류가 난 경우를 구분합니다. 손상된 레코드를 단순 종료로 처리하면 데이터 일부를 조용히 누락할 수 있습니다.

큰 결과는 모든 행을 메모리에 모으는 비용도 고려합니다. 스트리밍이나 결과 제한은 API 계약과 함께 정할 후보이며 현재 확정 기능은 아닙니다. 같은 실행기를 통해 스캔과 인덱스 결과가 동일한 형태로 나오는지 검증합니다.
