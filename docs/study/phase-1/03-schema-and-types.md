# 스키마와 자료형 확인

## SQL 문장만으로 알 수 없는 것

```sql
SELECT name FROM users WHERE id = '1';
```

파서는 '1'이 문자열이라는 것은 구분할 수 있지만, 이 문장만으로 users.id 컬럼이 정수인지 문자열인지 알 수 없습니다. 테이블의 스키마 정보가 더 필요합니다.

## 확인 흐름

```text
파싱: '1'을 문자열 값으로 기록
스키마 확인: users.id의 정의된 자료형 확인
조건 평가: 허용되는 비교라면 실제 행의 값에 조건 적용
```

자료형을 알아내기 위해 각 행의 id 값을 먼저 꺼내 보는 것으로 생각했지만, 컬럼의 정의된 자료형은 스키마에서 확인할 수 있다는 점을 이해했습니다.

스키마 확인 단계에서는 테이블과 컬럼이 존재하는지도 확인할 수 있습니다. SQL 문법이 맞는 것과 실제 테이블에서 의미가 있는 것은 별도의 문제입니다.

## 아직 결정하지 않은 것

정수 컬럼과 문자열 값을 비교할 때 변환을 허용할지, 오류로 처리할지는 DBMS 규칙에 따라 다릅니다. 이번 과제의 변환 정책과 스키마 저장 방식은 아직 결정하지 않았습니다.

## 예습: 스키마 검사에서 정할 계약

테이블 이름은 미리 정의한 스키마에서 찾고, 컬럼 이름을 해당 컬럼의 위치·자료형에 연결합니다. 같은 컬럼을 INSERT 목록에 두 번 지정했는지, 누락 컬럼을 허용할지도 검사해야 합니다.

숫자와 문자열을 자동 변환할지, 정수 범위 초과와 NULL을 허용할지, 자동 ID를 사용자가 지정할 수 있을지는 별도 정책입니다. 검사 실패는 파일 변경 전에 반환하는 것이 기본입니다. 스키마가 이미 존재한다는 과제 조건은 검사 자체를 생략한다는 뜻이 아닙니다.

스키마를 코드 상수나 설정 파일 중 어디에 둘지는 아직 선택하지 않았습니다. 검증에 통과한 값과 컬럼 순서를 저장 계층까지 같은 의미로 전달해야 합니다.
